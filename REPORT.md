## Архитектура: почему клиент главный

Сайт личный, ключи свои — значит сервер не обязан быть хранилищем. Всё состояние (разговоры, файлы,
настройки, ключи) живёт в IndexedDB браузера, запросы к провайдерам идут напрямую, если провайдер
отдаёт CORS-заголовки. Это даёт ноль затрат на инфраструктуру и ноль утечек через чужой бэкенд.

Серверные функции добавлены ровно там, где браузер бессилен:

- `/api/search` — DuckDuckGo без ключа (HTML-выдача, браузером блокируется по CORS);
- `/api/read` — чтение страницы в markdown с защитой от SSRF: приватные диапазоны адресов отсекаются;
- `/api/provider/[...path]` — прокси к провайдерам без CORS, заголовки пересылаются, `Cookie` вырезается;
- `/api/health` — какие источники поиска доступны, чтобы интерфейс не обещал лишнего.

Функции не хранят состояние и не логируют ключи. Один и тот же код работает и в dev-сервере Vite
(`build/api-dev.ts`), и на Vercel — локальная отладка не расходится с продакшеном.

Если сервера нет (чистый GitHub Pages), клиент деградирует по-честному: поиск уходит в открытые API
и в ключ, вписанный в настройках, чтение страниц — через открытый сервис r.jina.ai с явной пометкой,
запросы к провайдерам — напрямую.

## Провайдеры и модели: три источника правды

1. **Ответ провайдера** — список моделей из `/models` (или аналога). Даёт идентификаторы, которые
   действительно работают с вашим ключом.
2. **Каталог models.dev** — возможности, лимиты контекста, цены, модальности. Обновляется раз в
   6 часов, кэшируется в IndexedDB.
3. **Ручные уточнения** — то, что каталог не знает: заголовки, особенности протокола, пределы вывода.

Каждое поле несёт источник (`provider`, `catalog`, `manual`, `unknown`) и вес доверия: ручное 1,
ответ провайдера 0.9, каталог 0.75, неизвестное 0.2. При конфликте побеждает более доверенный
источник, а интерфейс показывает, откуда взялось значение — «от провайдера», «из каталога».

Протоколы разделены: `chat-completions` (большинство), `responses` (OpenAI-совместимые с новым
API), `messages` (Anthropic). Для каждого профиля заданы адрес, схема авторизации, версия API и
поведение в браузере — «напрямую» или «только через прокси».

Маршрутизация по возможностям: если во вложении изображение, а у выбранной модели нет `image` среди
входных модальностей, приложение ищет способную модель в том же пуле провайдера и предлагает её, а
не отправляет запрос, который заведомо упадёт. То же для инструментов, рассуждений и переполнения
контекста.

## Контекст и экономия

Токены считаются до отправки: 3.6 символа на токен для текста, отдельная оценка для изображений по
размеру, 4 токена overhead на сообщение, стоимость схем инструментов — по их размеру. Полоса
заполнения окна видна в строке состояния; при 85% (`autoCompactRatio`) старая часть истории
сжимается моделью в дайджест, хвост остаётся дословно.

Экономия — три режима: выключен, сбалансированный (по умолчанию), строгий. Режим меняет лимит
вывода, усилия рассуждений и добавляет инструкции о краткости. Отдельно: бюджет размышлений в
токенах, потолок стоимости разговора и предупреждение до того, как деньги кончатся. Служебные
задачи (заголовки, дайджесты) уезжают на маленькую дешёвую модель, если она подключена.

Стоимость считается по фактическому usage провайдера — вход, выход, чтение кэша, запись кэша,
рассуждения — и складывается в итог по разговорам и по дню.

## Рабочее пространство и исполнение

У каждого разговора своя папка. Модель работает одиннадцатью инструментами: поиск и чтение страниц,
`list_files`, `read_file`, `write_file`, `patch_file` (правка с diff), `delete_file`,
`search_files`, `run_command`, `run_javascript`, `save_artifact`.

Исполнение — два режима. WebContainer даёт настоящий Node.js и npm в браузере, но требует заголовков
`Cross-Origin-Opener-Policy` и `Cross-Origin-Embedder-Policy` (на Vercel они выставлены, на GitHub
Pages их поставить нельзя). Локальная песочница в воркере работает везде и исполняет JavaScript без
сети и файловой системы. Выбор делает `chooseRuntime`: проверяется кросс-оригинная изоляция и
поддержка браузера, причина выбора показывается в строке состояния — никаких молчаливых компромиссов.

Опасные действия идут через явное разрешение: команда, удаление файла, запись вне папки разговора.
Карточка одобрения показывает точный ввод команды до того, как что-либо запустится.

## Поиск

Модель сама решает, искать ли, и сама формулирует запрос — в системных инструкциях описано, когда
поиск уместен и что после него нужно читать источник целиком через `web_read`.

Источники по убыванию доступности: DuckDuckGo (без ключа, через функцию), затем открытые API —
Wikipedia, Hacker News, GitHub; при ключах — Brave, Tavily, Serper, свой SearXNG. Результаты
очищаются от разметки, дедуплицируются и обрезаются по числу, страница извлекается в markdown:
заголовок, описание, основной текст, без навигации и футера. Если источник не настроен, интерфейс
говорит об этом прямо, а не выдаёт пустоту.

## Дизайн

Сознательно не использованы приёмы, по которым узнают сгенерированные интерфейсы: кремовый фон с
терракотовым акцентом и контрастным серифом, почти чёрный фон с одной кислотной деталью, газетные
линейки и плотные колонки, набор одинаковых карточек с равномерной тенью и градиентной подложкой,
шаблонный хром — капс-надзаголовки, соединения через точку, подписи «СЛОВО — фрагмент»,
моноширинные ярлыки данных и стрелки везде.

Вместо этого — приборная панель: тёплая бумага `#F0EFEB` / графит `#14181B`, один янтарный акцент
для действия, состояния цветами точек (живо, занято, отказ), границы волосяные, скругления три
пикселя, тени почти не используются. Смелость потрачена в одном месте — на строке состояния и
ленте разговора, остальное тихо.

Четыре гарнитуры с кириллицой, все подключены локально: Unbounded для вывески, IBM Plex Sans для
интерфейса, Literata для чтения длинных ответов, JetBrains Mono для чисел, адресов и кода. Шаг
типа — шкала из семи размеров, отступы кратны четырём.

Раскладка: вывеска, рейка разговоров, лента, рабочая панель — на широком экране четыре области, на
узком одна область за раз с нижней навигацией. Строка ширины текста ограничена, фокус с клавиатуры
виден, `prefers-reduced-motion` уважается, движение только по действию пользователя.

Мобильная версия — не сжатая десктопная: листы становятся полноэкранными, композитор прилипает к
низу с учётом клавиатуры (`interactive-widget=resizes-content`), отступы учитывают safe-area,
цели нажатия не меньше 44 пикселей, приложение ставится на домашний экран через manifest.

## Развёртывание

Оба варианта бесплатные.

**Vercel** — кнопка `Deploy with Vercel` в README и в настройках приложения: репозиторий клонируется
в ваш GitHub, проект собирается, серверные функции поднимаются автоматически. Переменные окружения
не обязательны, поэтому в ссылку не зашит параметр `env` — деплой проходит в один клик без форм.
`vercel.json` задаёт сборку Vite, каталог `dist`, заголовки изоляции и переписывание маршрутов на
`index.html`, не задевая `/api`.

**GitHub Pages** — workflow `.github/workflows/deploy.yml`: типы, тесты, сборка с
`DEPLOY_TARGET=pages` (базовый путь `/site/`, `404.html` для прямых ссылок) и публикация `dist`.
Заголовки COOP/COEP на Pages недоступны, поэтому исполнение кода переключится на локальную
песочницу — и скажет об этом.

## Надёжность

Сообщение, не ушедшее из-за обрыва, попадает в очередь и отправляется, когда связь вернулась.
Повторы с экспоненциальной паузой различают отказ ключа, лимит провайдера, сетевую ошибку и отмену
пользователем — слепо повторять 401 бессмысленно. Монитор соединения меряет задержу до провайдера и
держит поток живым. Все данные выгружаются одним файлом и восстанавливаются обратно, включая
очередь и файлы рабочих папок.

## Тесты

223 теста в 19 файлах: каталог и автообнаружение, маршрутизация по возможностям, токены и сжатие,
повторы и разбор отказов, экономика, пути и patch, чтение и запись `opencode.json`, серверные
функции (поиск, извлечение, прокси, здоровье), сквозной тест интерфейса на jsdom — загрузка,
добавление провайдера с подтягиванием моделей, листы настроек, палитра команд, строка состояния.

## Ограничения честно

- DuckDuckGo без ключа — экспериментальный источник: выдача может закрыться антибот-проверкой,
  поэтому открытые API и ключи держатся как запасной слой.
- WebContainer работает не во всех браузерах и требует заголовков изоляции; на GitHub Pages
  доступна только локальная песочница без сети и npm.
- Оценка токенов приблизительная: точный токенайзер провайдера в браузере не запускается, поэтому
  числа в строке состояния — оценка с запасом, а не счёт из счёта.
- Ключи живут в IndexedDB браузера: для личного сайта это осознанный выбор, но на общем компьютере
  данные нужно выгружать и удалять.
- models.dev — внешний каталог: при его недоступности работают данные провайдера и ручные уточнения.

## Что я бы делал дальше

1. Шифрование ключей паролем (WebCrypto, PBKDF2) — сейчас они лежат в IndexedDB открыто.
2. Точные токенайзеры для основных семейств вместо оценки по символам.
3. Ветки разговора: ответвление с любой реплики с общим рабочим пространством.
4. Совместные рабочие папки между разговорами — сейчас папка строго своя.
5. Профили инструкций и пресеты хода, сохраняемые одним файлом и переносимые между устройствами.
6. Наблюдение за ценой: предупреждение, когда разговор стабильно дороже выбранного порога.
