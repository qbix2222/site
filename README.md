# Пульт

Личная консоль для работы с моделями: подключаете провайдера своим ключом, у каждого разговора —
свой контекст, своя папка с файлами и песочница, где модель может писать код и запускать команды.
Интерфейс собран как приборная панель, мобильная версия — не урезанная, а отдельная раскладка.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fqbix2222%2Fsite&project-name=pult&repository-name=pult)

Кнопка копирует репозиторий в ваш GitHub и разворачивает его на бесплатном тарифе Vercel вместе с
серверными функциями. Второй вариант — GitHub Pages: он описан ниже.

## Что умеет

**Провайдеры и модели**

- 12 готовых профилей: OpenRouter, Anthropic, OpenAI, Google, Groq, DeepSeek, xAI, Mistral, Z.ai,
  Nebius, Ollama, LM Studio — с правильными адресами, схемами авторизации и протоколами
  (`chat-completions`, `responses`, `messages`).
- Автоматический опрос моделей при добавлении: список берётся у самого провайдера и сверяется с
  каталогом [models.dev](https://models.dev/api.json) (обновляется раз в 6 часов).
- Возможности каждой модели — из каталога, ответа провайдера и ручных уточнений, с уровнем
  доверия: текст, изображения, аудио, PDF, вызов инструментов, рассуждения, поток, лимиты контекста
  и цены за миллион токенов.
- Фильтр по возможностям: модель без зрения не получит фотографию — приложение либо предложит
  маршрутизацию на способную модель из того же пула, либо честно скажет, чего не хватает.
- Свои провайдеры: адрес, протокол, схема ключа, заголовки, путь автообнаружения моделей, режим
  браузера или прокси — всё в форме добавления.
- Профиль **opencode**: переключатель при добавлении провайдера. Включён — приложение читает
  `opencode.json` и пишет в него (лимиты контекста, бюджеты размышлений, `baseURL`, `apiKey` через
  `{env:VAR}`), а экспорт настроек даёт файл, который понимает opencode IDE и CLI.

**Разговор и контекст**

- У каждого разговора своя история, своя папка файлов, свои настройки хода (модель, температура,
  лимит ответа, усилия рассуждений, бюджет размышлений, многословность).
- Подсчёт токенов до отправки: текст, вложения, схемы инструментов, служебный overhead. Полоса
  заполнения окна видна всегда, при пороге история сжимается в дайджест.
- Очередь неотправленных сообщений: запрос не теряется при обрыве сети и уходит, когда связь
  вернулась.
- Монитор соединения: задержка до провайдера, живые повторы с экспоненциальной паузой, разбор
  отказов (ключ отклонён, лимит, сеть, отмена).

**Рабочее пространство и исполнение**

- 11 инструментов модели: `web_search`, `web_read`, `list_files`, `read_file`, `write_file`,
  `patch_file`, `delete_file`, `search_files`, `run_command`, `run_javascript`, `save_artifact`.
- Файлы добавляете вы (перетаскивание, выбор, вставка) и пишет модель — всё в одной папке
  разговора, с историей версий и diff для правок.
- Исполнение кода в двух режимах: WebContainer (настоящий Node.js в браузере, нужен COOP/COEP) и
  локальная песочница в воркере. Режим выбирается сам, с объяснением, почему выбран именно он.
- Опасные действия — через явное разрешение: команда, запись вне папки, удаление.

**Поиск в интернете**

- Модель сама решает, искать ли, и сама формулирует запрос; результаты читаются целиком через
  извлечение страницы в markdown.
- Бесплатно и без ключа: DuckDuckGo через серверную функцию, плюс открытые API (Wikipedia,
  Hacker News, GitHub) как запасной слой.
- Ключи не обязательны, но поддерживаются: Brave, Tavily, Serper, свой SearXNG — на сервере или
  прямо из браузера.

**Экономия и лимиты**

- Три режима экономии: выключен, сбалансированный, строгий — меняют лимиты ответа, усилия
  рассуждений и добавляют инструкции о краткости.
- Бюджет размышлений и усилий (`thinkingBudget`, `reasoningEffort`), лимит вывода, потолок
  стоимости разговора и общий потолок в долларах с предупреждением до отказа.
- Маленькая модель для служебных задач (заголовки, дайджесты) — выбирается сама из подключённых.
- Учёт стоимости по факту использования: вход, выход, кэш, рассуждения — в строке состояния.

**Интерфейс**

- Тёмная и светлая темы, плотность, уважение к `prefers-reduced-motion`, полная работа с
  клавиатуры, палитра команд `Ctrl/⌘+K`.
- Мобильная раскладка: нижняя навигация, полноэкранные листы, безопасные отступы под «чёлку»,
  крупные цели нажатия, установка на домашний экран (manifest).
- Экспорт и импорт всех данных, резервная копия разговоров и настроек.

## Как устроено

```
src/
  core/       типы, провайдеры, возможности, маршрутизация, токены, экономика, деплой-справка
  catalog/    автообнаружение моделей, каталог models.dev, чтение и запись opencode.json
  engine/     соединение, повторы, сжатие истории, заголовки, параметры модели
  agent/      инструменты модели, инструкции, одобрения, транспорт
  workspace/  файлы разговора, пути, patch и diff
  runtime/    WebContainer и локальная песочница
  store/      zustand-хранилища и IndexedDB
  ui/         экраны и листы
  styles/     tokens.css (краски, шрифты, ритм) и base.css (вся разметка)
server/       логика серверных функций: поиск, извлечение страниц, прокси, защита от SSRF
api/          точки входа Vercel: /api/health, /api/search, /api/read, /api/provider/[...path]
build/        плагин dev-сервера, чтобы те же функции работали локально
```

Клиент работает и без сервера: поиск уходит в открытые API и в ключ, вписанный в настройках,
запросы к провайдерам идут напрямую, если провайдер отдаёт CORS-заголовки. Серверные функции
добавляют три вещи, которые браузер сам не может: DuckDuckGo без ключа, чтение страниц с защитой от
SSRF и прокси к провайдерам без CORS.

Данные живут в IndexedDB браузера: разговоры, файлы, настройки, ключи. Сервер ничего не хранит и
ничего не логирует, ключи провайдеров не покидают ваш браузер, кроме самого запроса к провайдеру.

## Переменные окружения

Все необязательные — без них приложение работает.

| Переменная           | Зачем                                                       |
| -------------------- | ----------------------------------------------------------- |
| `ALLOWED_ORIGIN`     | домен сайта для CORS серверных функций                      |
| `BRAVE_API_KEY`      | поиск Brave, есть бесплатный тариф                           |
| `TAVILY_API_KEY`     | поиск Tavily, есть бесплатный тариф                          |
| `SERPER_API_KEY`     | выдача Google через Serper                                    |
| `SEARXNG_URL`        | адрес своего экземпляра SearXNG                               |
| `PROXY_ALLOW_LOCAL`  | `1` разрешает прокси на локальные адреса, только разработка   |

## Запуск локально

```bash
npm install
npm run dev          # сайт и серверные функции на http://localhost:5173
npm test             # 223 теста
npm run build        # production-сборка
npm run preview      # проверка сборки
```

## Развёртывание

**Vercel** — кнопка выше или `vercel` в консоли. `vercel.json` уже задаёт сборку Vite, каталог
`dist`, заголовки `Cross-Origin-Opener-Policy` и `Cross-Origin-Embedder-Policy` (без них
WebContainer не запустится) и переписывание маршрутов на `index.html`, не задевая `/api`.

**GitHub Pages** — в настройках репозитория включите Pages со источником «GitHub Actions», затем
push в `main`. Workflow `.github/workflows/deploy.yml` прогоняет типы и тесты, собирает с
`DEPLOY_TARGET=pages` (базовый путь `/site/`, страница `404.html` для прямых ссылок) и публикует
`dist`. Заголовки COOP/COEP на Pages недоступны, поэтому исполнение кода переключится на локальную
песочницу и скажет об этом в строке состояния.

## Тесты

223 теста в 19 файлах: разбор каталога моделей, автообнаружение, маршрутизация по возможностям,
подсчёт токенов и сжатие истории, повторы и разбор отказов, экономика, пути и patch рабочей папки,
чтение и запись `opencode.json`, серверные функции (поиск, извлечение, прокси, здоровье), сквозной
тест интерфейса на jsdom — загрузка, добавление провайдера, листы и палитра команд.

Логика решений и ограничения — в [REPORT.md](REPORT.md).
